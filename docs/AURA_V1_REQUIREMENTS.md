# AURA V1 Requirements

**Project:** AURA AI Desk Assistant
**Roadmap:** 90-Day AURA Development Roadmap
**Phase:** Phase 1 — Audit and Architecture
**Day:** 2 — Freeze AURA V1 Requirements
**Status:** V1 Scope Frozen

---

## 1. Purpose

This document defines the features and hardware that are required for the AURA V1 prototype during the 90-day development roadmap.

The purpose of freezing the requirements is to clearly define the V1 scope and prevent unnecessary feature expansion during development.

---

# 2. Current Hardware Availability

All currently required hardware components are available.

* **Missing components:** None
* **Damaged components:** None

All available hardware should still be individually verified during the appropriate hardware testing stages of the roadmap.

---

# 3. Required Hardware

The following hardware is required for AURA V1:

* [ ] ESP32
* [ ] 3.5-inch touchscreen display
* [ ] Touch input/controller
* [ ] DHT22 temperature and humidity sensor
* [ ] DS3231 real-time clock
* [ ] MicroSD card/storage
* [ ] DFPlayer Mini
* [ ] Speaker
* [ ] INMP441 microphone
* [ ] PIR motion sensor
* [ ] Camera

---

# 4. Required Connectivity and Intelligence

AURA V1 must include:

* [ ] Wi-Fi connectivity
* [ ] Cloud AI
* [ ] Command processing
* [ ] Decision Engine
* [ ] Error handling

---

# 5. Required Applications and Modes

AURA V1 must include:

* [ ] Study Mode
* [ ] Exhibition Mode
* [ ] Professional user interface (UI)

---

# 6. Explicitly Excluded From AURA V1

The following features are **not part of the AURA V1 prototype**:

* [ ] Wheels
* [ ] Motors
* [ ] Navigation
* [ ] Obstacle avoidance
* [ ] Autonomous movement

AURA V1 is designed as a **stationary AI Desk Assistant**.

# 8. Scope Rules

During V1 development:

1. The required features listed in this document are the primary development scope.
2. New features should not be added without reviewing their effect on the roadmap.
3. Features explicitly excluded from V1 should not be developed as part of the main 90-day roadmap.
4. Hardware availability does not mean that every component is already integrated or fully tested.
5. Hardware and software will be verified progressively according to the roadmap.
